## 1. Compliance Status Taxonomy & Definitions

Every extracted requirement is assigned an evidence-backed compliance status:

- `PASS_VERIFIED`: Implemented in source code, backed by reproducible automated tests or verified schema/API artifacts.
- `PARTIAL`: Core mechanism exists in code, but minor operational edge cases, UI connections, or background handlers are incomplete.
- `FAIL`: Verified source behavior directly violates the stated specification or contains a confirmed bug.
- `NOT_IMPLEMENTED`: Demonstrably absent from the codebase (no models, routes, or services exist).
- `NOT_VERIFIED`: Code exists, but runtime verification is impossible without staging infrastructure, physical devices, or live credentials.
- `BLOCKED`: Implementation or verification cannot proceed due to an external dependency (e.g., third-party contract, legal signoff).
- `NOT_APPLICABLE`: Requirement intentionally superceded or not applicable to current architecture.
